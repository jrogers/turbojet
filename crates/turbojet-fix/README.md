# turbojet-fix

FIX application messages for [Turbojet](https://github.com/jrogers/turbojet), one module per FIX
version, each behind a feature of the same name: `fix40`, `fix41`, `fix42`, `fix43`, `fix44`,
`fix50`, `fix50sp1` and `fix50sp2`. None is on by default, so a build compiles only the versions it uses. Each module has
an enum per enumerated field, a struct per message and repeating-group entry, and a tag constant
per field (in `tags`). Session-level messages are in `turbojet::admin`.

```toml
[dependencies]
turbojet-fix = { version = "0.4", features = ["fix44"] }
```

```rust
use turbojet::{FixMessage, FixMessageRef};
use turbojet::fields::{FromFix, UtcTimestamp};
use turbojet_fix::fix44::{NewOrderSingle, NewOrderSingleRef, OrdType, Parties, PartyRole, Side};

let now = UtcTimestamp::from_fix("20260928-12:00:00.000").unwrap();
let mut order = NewOrderSingle::new("ORD1", Side::Buy, now, OrdType::Market);
order.symbol = Some("AAPL".into());
let mut firm = Parties::new("FIRM");
firm.party_role = Some(PartyRole::ExecutingFirm.into());
order.party_ids.push(firm);
let msg = order.to_message();
let parsed: NewOrderSingle = msg.parse().unwrap();
assert_eq!(parsed, order);
let borrowed: NewOrderSingleRef = msg.parse().unwrap();
assert_eq!(borrowed.into_owned(), order);
```

Each message and group also has a borrowed form, such as `NewOrderSingleRef`, whose strings and
groups borrow from the received message rather than copying it: read messages with it, and call
`into_owned()` to keep one.

From FIX 4.3 on, components such as Instrument and OrderQtyData are flattened into the messages
that use them (`order.symbol`, `order.order_qty`); repeating groups, Parties among them, are
structs with their official names.

Enumerated fields are typed `turbojet::fields::Code<E>`: a code the dictionary lists is
`Code::Known`, and any other is kept as `Code::Unknown` rather than failing the parse, as in
QuickFIX, so a venue's own value in a field the application never reads doesn't cost the message.
Compare a field with a value directly (`order.side == Side::Buy`), and set one with `.into()`. To
reject unknown codes, check messages against a data dictionary (`SessionConfig::with_dictionary`,
feature `validation`), which answers them with a Reject, or generate your own messages with
`--strict-enums`. To name a venue's extra values, merge its dictionary and generate your own
(`turbojet-codegen OrchestraFIX44.xml --merge venue.xml`, or `Dictionary::merge_file` in a
`build.rs`).

The code is generated by `turbojet-codegen` from the FIX Orchestra files in
`dictionaries/orchestra`: the official ones for FIX 4.2 and 4.4, and for the other versions files
converted from the FIX Trading Community's FIX Unified Repository (2010 Edition), since they
aren't among their published Orchestra files. Groups and enum values have their official names,
and each item's docs give its FIX name and tag. Don't edit the generated modules, run
`scripts/codegen.sh`.
