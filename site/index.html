Turbojet is the FIX session layer and everything around it, as a library: a codec, the session state machine (logon, sequence numbers, gap detection and resends, heartbeats, logout), storage, and TCP and TLS acceptors and initiators, with typed messages for FIX 4.0, 4.1, 4.2, 4.3, 4.4, 5.0, 5.0 SP1 and 5.0 SP2 generated from the FIX Trading Community's official data. For binary order entry it has SBE codecs and FIXP sessions, and for market data a FAST codec.

Pre-1.0, and not yet proven in production. Turbojet is tested against QuickFIX/J and QuickFIX/n and through QuickFIX's scripted acceptance scenarios, and its parsers and session state machine are fuzzed, but it hasn't been certified with any venue or run against a real counterparty, and its APIs will change before 1.0. Test it thoroughly yourself before trading real money with it. It is provided as is, without warranty of any kind.

Built for systems that can't lose a fill

Safe

Everything a counterparty sends is bounded, invariants are asserted, and the session runs against itself in a deterministic simulator through crashes, store failures and power loss.

Pure Rust

No bindings to a C++ or Java engine, and no unsafe code in the engine.

Fast

About 1 µs from an order to its acknowledgement, wire to wire, and no allocations on that path, counted on every test run.

Embeddable

A library, not a server: every layer is public, from the codec through the sans-IO session to the transports.

The crates

  • turbojet: the engine, with SBE, FIXP and (feature fast) FAST.
  • turbojet-fix: every FIX 4.0 to 5.0 SP2 application message, a feature per version.
  • turbojet-config: an acceptor and initiators from a TOML file, reloaded while running.
  • turbojet-sql: session storage in SQLite or PostgreSQL.
  • turbojet-dictionary and turbojet-codegen: FIX Orchestra and QuickFIX dictionaries, and typed messages generated from them.
  • turbojet-log: prints and filters message logs with FIX field names.
